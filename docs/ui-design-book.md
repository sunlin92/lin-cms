# Lin CMS 前端 UI 设计书

**版本** 1.0  
**适用范围** `lin-cms-react/` 管理后台  
**设计基线** Lin CMS 产品需求与 API 契约、当前 React 前端实现、旧 Vue 版交互参考，以及 Refactoring UI 的设计原则

## 1. 设计目标

Lin CMS 面向需要维护用户、分组、权限、图书和操作日志的后台使用者。界面需要让管理员快速定位功能、确认当前状态并完成操作，也要让普通用户容易维护个人资料和查看获授权的内容。

本次 UI 优化聚焦三个结果。

- 页面层级清楚，导航与当前工作位置容易辨认。
- 表格、筛选器和表单在桌面与移动端都能操作。
- 动效帮助用户理解状态变化，不拖慢日常管理操作。

视觉可以重做，信息架构、业务步骤、权限边界、路由和 API 契约保持现状。UI 设计不得借机增加通知中心、实时推送、多租户、富文本发布流或 Excel 导入导出等未纳入本期范围的能力。

## 2. 设计原则

### 2.1 面向后台任务

后台用户主要执行查找、比较、编辑和确认。页面空间优先留给业务内容，避免大幅插画、渐变背景和重复的装饰卡片。工作台可以呈现趋势和摘要，其余页面以数据与操作为中心。

### 2.2 清楚的视觉层级

页面标题说明当前任务，主操作在标题区域清晰可见，筛选和辅助动作次之，说明文字与时间等元数据降低对比度。用字号、字重、间距和颜色共同建立层级，不靠把所有重要内容都放大处理。

### 2.3 信息密度适中，数据页可扫描

全局采用中等密度；用户、分组、图书和日志页可提高密度。表格字段按内容对齐，数值列右对齐，行操作不抢占主要数据区域。分组、间距与背景区分信息，不用粗重边框包住每一个元素。

### 2.4 一致但不机械

共用按钮、表单、表格和反馈组件遵守同一套 token 与状态规则。卡片依场景承担不同职责。统计卡突出数值，表单面板组织输入项，列表容器承载数据。所有卡片不套用同一套悬浮效果。

### 2.5 操作反馈及时

加载、保存、删除、无数据、无搜索结果和无权限都需要有明确反馈。错误出现在对应操作或字段附近，成功反馈简短，不打断用户继续工作。

## 3. 用户与界面语气

主要用户是中文环境中的 CMS 管理员和内容维护人员。按“专业、可信、平静”的方向设计，表达正式但不生硬。默认不使用俏皮插画、拟物效果或强烈营销语气。

- 菜单、按钮和提示采用直接的中文动作词，例如“新增用户”“保存更改”“删除图书”。
- 操作完成后说明结果；失败提示尽量包含可执行的修正方向。
- 权限不足、会话失效和数据为空属于不同状态，使用各自的文案和操作建议。
- 图标辅助识别，不能取代重要按钮的文字标签；纯图标按钮必须有可访问名称和悬浮提示。

## 4. 信息架构与导航

### 4.1 主导航分组

保留当前路由与权限驱动菜单，将可见导航按现有分区组织。

| 分区 | 页面 | 主要任务 |
| --- | --- | --- |
| 总览 | 仪表盘、关于 | 查看工作台摘要和项目说明 |
| 图书管理 | 图书列表、新增图书 | 查询、创建、编辑或按权限删除图书 |
| 系统 | 日志管理 | 按条件筛选并查看操作记录 |
| 权限管理 | 用户列表、新建用户、分组管理、新增分组 | 管理账号、分组和权限 |

个人中心通过顶栏用户菜单进入。新增/编辑等不出现在侧栏的页面仍需在面包屑中显示完整位置。

### 4.2 后台壳结构

桌面布局由侧栏、顶栏和主内容区组成。主内容区包含面包屑、页面标题、主操作、筛选/说明及页面主体。侧栏菜单和路由继续共用现有配置与权限判断，不能出现“菜单可见但路由拒绝”或“有权限但入口消失”的不一致。

规划文档中的侧栏搜索、`Ctrl/Cmd+K` 命令面板、多页签和全局搜索属于布局能力目标。若当前版本尚未实现，应在开发计划中分阶段补齐；设计稿和验收说明不得将其描述为已上线。命令面板首期只可覆盖现有路由导航，不能暗示未支持的业务搜索或新增服务端能力。多页签上限为 12 个，并按既定存储策略恢复。

### 4.3 权限呈现

权限同时影响菜单、路由和操作按钮。无权限的操作不显示或明确禁用，选择一种一致策略并遵循既定权限要求。Root 用户以 `level=ROOT` 判定。视觉层级不得暗示普通用户可执行仅 Root 可用的管理操作。

## 5. 布局与响应式规范

### 5.1 桌面工作区

- 视口宽度 ≥1280 px，侧栏默认展开，宽度沿用约 244 px；可折叠至约 68 px。
- 顶栏高度约 56 px，保持在视口顶部；其内容只放全局导航、面包屑和账户/主题入口。
- 主内容区使用独立滚动容器，侧栏导航单独滚动，避免长页面把导航一并带出视口。
- 页面内容最大宽度约 1200 px，居中显示；宽表格可使用更宽的容器，但不能压缩文字或操作列。
- 桌面主内容左右内边距约 24–32 px，页面区块间距 24–32 px。

布局骨架建议如下。

```text
┌────────────┬──────────────────────────────────────────┐
│ 品牌       │ 顶栏：菜单 / 面包屑 / 主题 / 用户          │
│ 导航分组   ├──────────────────────────────────────────┤
│ 导航项目   │ 页面标题                         主操作   │
│            │ 筛选与说明                                │
│            │ 页面内容，包括表格、表单或仪表盘           │
└────────────┴──────────────────────────────────────────┘
```

### 5.2 平板与移动端

- 768–1279 px，侧栏默认折叠，主内容使用可读宽度；筛选工具可换行或收进筛选面板。
- <768 px，侧栏改为左侧抽屉并提供遮罩；选中菜单后自动关闭，按下 `Escape` 关闭，焦点留在合理位置。
- 375 px 起确保主要页面无内容遮挡。页面水平边距约 16 px，区块间距约 16–24 px。
- 交互目标最小 44×44 px；图标按钮视觉尺寸可以更小，但点击区域需补足。
- 不能仅为适配宽度而隐藏仍有业务价值的信息。应调整顺序、换行、折叠次级筛选或采用卡片行。

### 5.3 内容宽度与滚动

页面整体避免横向溢出。长表格保留可控的横向滚动，并让表头、首要识别字段和行操作保持可用。表单页面建议限制在约 720 px，说明性内容控制阅读行宽。侧栏、顶栏和正文分别定义滚动责任，页面滚动位置在导航后按一致规则复位或保留。

## 6. 页面设计说明

### 6.1 登录

使用单栏登录面板，突出产品名称、用户名/密码输入和登录操作。验证码开启时将验证码作为正常字段加入表单，不改变输入顺序。错误提示靠近表单，登录按钮显示提交状态并避免重复提交。背景保持安静，不使用大面积渐变或无关插画。

### 6.2 仪表盘

工作台面向快速了解当前管理状况。页面标题与简短欢迎语之后放用户数、分组数、图书数和日志数等摘要；趋势图和最近日志按重要程度排列；快捷入口按用户权限显示。统计卡采用紧凑数值布局，只有存在可信历史数据时才展示趋势线。无数据时说明数据来源或等待条件，不伪造趋势。

### 6.3 用户与分组

列表页按“标题和新增入口 → 筛选区 → 结果表格 → 分页”组织。主要筛选项始终可见，低频条件可折叠。用户行操作收进操作菜单或紧凑按钮组，删除和重置密码与普通查看动作在视觉上区分。内置分组保护状态需要可读说明。

新建用户表单按账号信息与分组信息分组，字段标签固定在输入框上方。分组权限页按模块呈现权限树，展示全选、半选和单选状态；保存区说明将提交的差异范围，避免用户误以为会覆盖全部权限。

### 6.4 图书

图书列表优先展示识别图书所需字段与编辑入口，新增按钮位置固定在页面标题区域。窄屏采用可读的卡片行，图书名和主要信息优先，编辑/删除收纳到行操作菜单。新增和编辑共用表单结构，字段标签、校验提示和提交/取消位置保持一致。删除继续使用二次确认，并明确说明目标图书。

### 6.5 日志

日志属于高密度检索界面。筛选条件按关键词、用户、日期等相关性分组；搜索和重置操作紧邻筛选项。结果区域突出时间、用户、方法和路径等定位信息，长内容换行或在详情中查看，不能无限撑宽表格。关键字高亮使用安全的文本分段渲染。加载更多时保留已加载记录，并在列表末尾显示加载状态。

### 6.6 个人中心

采用单栏或窄双栏分组，依次呈现头像与基本资料、账户信息、密码修改。头像裁剪有清晰的预览和取消路径。修改密码的影响在提交前说明；成功后遵循现有会话失效和重新登录流程。

### 6.7 关于与错误页

关于页采用内容阅读布局，项目介绍、技术栈和版本信息清楚分组。窄屏内容按顺序重排，不因断点隐藏信息。404 页面简要说明地址不可用，并提供返回工作台的主操作。

## 7. 视觉设计系统

### 7.1 色彩

延续当前四套低饱和主色预设，包括靛青 `lin-classic`、栗褐 `book-ink`、胭脂 `palace-vermilion` 和黛绿 `ru-yao-celadon`，并保留浅色/深色模式。主题主要色用于主操作、焦点和导航选中状态；大面积页面表面使用中性背景。避免默认全屏蓝紫渐变。

颜色统一从语义 token 读取。需覆盖页面背景、卡片、弹出层、主文字、次级文字、边框、主色、焦点环、侧栏和状态色。成功、警告、错误、信息状态同时使用文字或图标表达，不能只靠颜色区分。新增表面 token 前先确认浅色、深色和四套主色预设下的对比关系。

### 7.2 字体与层级

沿用系统中文无衬线字体栈。正文建议 14–16 px，说明文字 12–14 px，页面标题 24–30 px，区块标题 18–20 px。数值和表格数字使用等宽数字特性，避免列内数字跳动。正文行高约 1.5，标题行高约 1.2–1.35。通过字重控制在 400、500、600 三档为主。

### 7.3 间距、圆角与边界

以 4 px 为基础，优先使用 4、8、12、16、24、32、48 px 间距。字段与标签相距 6–8 px，相关字段间隔 16–20 px，内容区块间隔 24–32 px。标准面板内边距 20–24 px，窄屏缩至 16 px。

圆角维持克制且一致。输入框与按钮约 6–8 px，普通卡片约 10–12 px，标签和头像按形状需求圆形。阴影只用于弹层、菜单、对话框等浮层；一般卡片优先通过留白和轻边界区分。

### 7.4 按钮和表格

主按钮用于当前页面最重要的提交或新增动作；次按钮使用描边或幽灵样式；危险操作默认弱化，确认界面再明确显示危险语义。按钮文字以动词开头，加载时保留按钮宽度并提供状态说明。

表格行高建议 44–52 px，表头固定在可滚动区域顶部。文字左对齐，日期和数值列按内容右对齐或使用 tabular numerals。可排序字段展示排序状态；hover 只提供轻微背景反馈。操作列宽度保持合理，次要操作用菜单承载。

## 8. 动效与交互规范

### 8.1 动效原则

动效既说明空间关系、状态变化和操作结果，也是 Lin CMS 视觉体验的一部分。页面首次进入时可以使用细腻的淡入上移、适度的交错入场和品牌区域的柔和显现；侧栏、抽屉与页签切换应连贯流畅，卡片和导航可以保留轻量的悬浮、弹簧与高亮反馈。动效要有层次，避免多个大幅位移或强烈模糊同时争夺注意力，也避免数据每次刷新都完整重播入场流程。

### 8.2 时长与缓动

| 场景 | 建议时长 | 动作 |
| --- | ---: | --- |
| 按钮、图标、背景 hover/focus | 140–220 ms | 颜色、透明度或轻微缩放，使用自然 ease 曲线 |
| 下拉菜单、提示、局部展开 | 180–260 ms | 淡入并移动 4–8 px，轻微缩放 |
| 侧栏折叠、导航抽屉 | 280–420 ms | 宽度或位置使用弹簧过渡，遮罩同步淡入淡出 |
| 路由内容切换 | 260–380 ms | 淡入上移 6–10 px，使用 ease-out 或低回弹 spring |
| 对话框打开/关闭 | 220–320 ms | 遮罩淡入，面板轻微缩放或上移 |

进入动效使用 ease-out，退出使用 ease-in；侧栏和导航指示器可以使用低回弹 spring，强调空间变化但不做明显弹跳。普通 hover 与反馈保持短促，路由切换和抽屉可使用更完整的过渡时间，保证连贯感而不拖慢操作。执行成功的反馈优先采用状态文本、toast 或图标变化，不为结果添加长动画。

### 8.3 各区域动效

- **侧栏**：折叠时使用连贯的宽度过渡；品牌标记、分区标题和菜单标签可错峰显现。激活态指示器沿菜单平滑移动，采用低回弹 spring。
- **移动抽屉**：从左侧滑入/滑出，遮罩同步淡入/淡出；导航内容可轻微错峰出现。背景页面保持静止，遮罩透明度遵循主题与可读性。
- **路由切换**：内容区使用柔和的淡入上移，避免页面切换时闪白或突然跳位。工作台卡片可适度错峰入场；普通列表不因每次刷新都重播整组动画。
- **卡片**：可点击卡片和快捷入口可有轻微悬浮、阴影与图标反馈；纯展示统计卡使用更安静的数值变化或淡入。鼠标悬浮不应成为触屏用户获取信息的唯一途径。
- **表格与筛选**：查询刷新以按钮 loading、骨架屏或局部状态反馈为主；筛选后可对新结果做轻微淡入，但不清空整页再重播动画。
- **对话框与菜单**：遮罩和面板的进出同步，面板可轻微缩放并上移；关闭时不延迟恢复页面可操作性。

### 8.4 减少动态效果

尊重 `prefers-reduced-motion`。默认偏好下保留完整、连贯的装饰性动效；用户开启减少动态效果时，取消大幅位移、缩放、模糊和交错延迟，改用即时状态切换或短淡入。除 CSS 媒体查询外，Motion 动画也应显式遵循用户设置，并对无障碍路径做测试。

## 9. 无障碍与状态设计

- 所有表单控件有可见标签；必填、错误和帮助信息通过语义关系与输入关联。
- 所有可操作控件可用键盘访问，并保留清晰的 `focus-visible` 焦点环。
- 使用语义化标题、导航、主内容区域和按钮；导航使用链接，动作使用按钮。
- 页面文字和控件对比达到 WCAG 2.1 AA 基本要求；颜色不是唯一的状态提示。
- 对话框打开后焦点进入对话框，关闭后返回触发控件；移动端抽屉可用 `Escape` 关闭。
- 骨架屏不应被屏幕阅读器误读成真实内容；加载状态提供可读文本或 live region。
- 空状态说明为何为空，并提供适用的下一步；无权限状态不伪装成无数据。

标准状态需要覆盖初次加载、局部刷新、无数据、无搜索结果、字段错误、请求失败、提交中、提交成功、无权限和会话失效。状态反馈不改变服务端错误码或响应处理契约。

## 10. 技术落地约束

- 继续使用 React 19、TypeScript、Tailwind CSS 4、Radix、Motion、现有本地 UI 组件和 CSS 语义 token。
- 新增视觉值优先进入 token 或现有组件变体，不在页面中散落硬编码色值。
- 保持 `routes.tsx` 作为路由与菜单元数据单一来源，权限过滤沿用现有授权逻辑。
- 不修改 API 路径、字段、分页、权限名称、错误语义和既定表单规则。
- 不为了动效引入新的独立运行服务或额外 UI 框架。新增第三方依赖前先核对官方文档与锁文件。
- 每个源文件不超过 800 行、每个函数不超过 100 行；遵守 TypeScript strict 和 Biome 规则。

## 11. 优化优先级

### P0：布局与可用性

1. 明确视口高度、侧栏滚动和主内容滚动的边界。
2. 完善移动端抽屉的打开/关闭状态动画、遮罩和键盘交互。
3. 检查用户、图书、分组和日志在 375 px 宽度下的布局；将低频行操作收纳，保留必需信息。
4. 检查标题区、主操作、筛选区和结果区的视觉层级。

### P1：动效与主题

1. 完善路由、抽屉和页面入场的连贯过渡，保留有层次的装饰性动效；数据刷新只更新需要反馈的区域，避免无关内容整页重播。
2. 验证 Motion 对减少动态效果偏好的支持，并补充测试。
3. 扩充并核验语义 token 在四套主题及深色模式下的可读性。
4. 检查弹窗、下拉菜单和提示的实际构建样式与焦点行为。

### P2：布局能力补齐

按产品规划逐项实现侧栏搜索、`Ctrl/Cmd+K` 命令面板、多页签恢复和全局搜索入口。每项需要先确认对应的前端范围、权限表现和数据来源，再安排开发；不因设计书自行增加后端接口。

## 12. 验收清单

### 视觉与布局

- [ ] 桌面、平板和 375 px 移动视口均无主内容遮挡或不可达操作。
- [ ] 桌面侧栏可折叠，长页面滚动时侧栏导航仍可访问。
- [ ] 表格在窄屏下保持可读，行操作可触达；必要时横向滚动范围明确。
- [ ] 页面标题、主操作、筛选与数据内容的层级一致。
- [ ] 浅色、深色和四套主色预设均使用语义 token，状态对比清晰。

### 动效与可访问性

- [ ] 抽屉、对话框、菜单和路由切换时长符合本设计书范围，关闭不拖延用户操作。
- [ ] 表格刷新不会触发整表明显重播动画。
- [ ] 开启减少动态效果后，位移、缩放、模糊和 stagger 被移除或明显降低。
- [ ] 键盘可完成导航、表单、弹层和确认操作，焦点可见且顺序合理。
- [ ] 所有图标按钮有可访问名称，表单错误与对应字段关联。

### 契约与回归

- [ ] 权限、路由、分页与业务操作流程保持现有约定。
- [ ] 前端没有绕开 `src/lib/api/` 的裸接口调用。
- [ ] 登录、图书 CRUD、用户管理、日志筛选等现有 E2E 主流程继续通过。
- [ ] 运行 `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`；涉及关键流程或断点变化时运行 `pnpm test:e2e`。
- [ ] E2E 执行前确认 `playwright.config.ts` 会重置的测试数据库可安全重建。
