# Lin CMS Agent 接入改造：需求澄清

> 文档版本：v0.1（待评审）  
> 日期：2026-10-20  
> 依据：现有 [需求澄清](./00-requirements-clarification.md)、[规划计划书](./01-planning-proposal.md)、[实现实施方案](./02-implementation-plan.md) 与用户确认的 Agent 接入方向  
> 对应技术规格：[Agent 接入技术规格书](./04-agent-access-technical-spec.md)

## 1. 任务理解

Lin CMS 当前以前后端管理界面为主要入口，权限由代码中固定声明并同步到数据库，认证依赖用户登录后签发的短期 JWT。新的目标是让没有专门培训的使用者能低成本把 CMS 接入本机或远程 AI Agent，并可通过清晰、可配置的内容模型、角色授权和专用 Token 安全地开放内容能力。

本次是对已完成重建项目的增量架构改造规划，不重写现有 CMS。改造应保留旧 `/cms/**`、`/v1/**`、`/health` API 线格式与既有认证/RBAC 行为；新增面向可配置内容与 Agent 的能力，并使浏览器、MCP 与 CLI 共用同一套服务端业务和授权规则。

## 2. 目标用户与成功结果

### 2.1 目标用户

- **CMS 管理员**：配置内容类型、用户分组（作为角色）的内容操作权限，并管理系统级安全边界。
- **普通 CMS 用户**：无需掌握 API、SQL 或 MCP 协议细节，通过界面创建自己使用的 Agent Token，查看和吊销凭证。
- **Agent 使用者**：在本机或远程 MCP 客户端中复制通用配置，连接 CMS 后按其 Token 获准的范围查询或维护内容。

### 2.2 成功结果

1. 新用户可在向导帮助下创建内容类型、创建最小内容记录，并让 Agent 通过 MCP 完成同一记录的查询/维护。
2. 用户无需自行编写 MCP Server、HTTP 客户端、数据库脚本或权限代码。
3. 管理员可按“用户分组/角色 × 内容类型 × 操作”配置能力，不因新增内容类型而改代码或重新部署。
4. Agent 凭证可单独命名、限定范围、设定过期时间、查看最近使用和立即吊销；泄露一个 Agent Token 不等于泄露用户登录凭证。
5. CLI 作为跨平台单文件可执行程序，能验证 CMS 地址与 Token、执行连通性测试、生成通用 MCP 配置并启动本机 `stdio` MCP 适配器。
6. 所有 Agent 操作在服务器端校验当前用户授权和 Token 范围，并形成不含秘密或完整内容负载的审计记录。

## 3. 已确认的范围与决策

| 主题 | 确认决策 |
| --- | --- |
| 接入形态 | 首发同时支持本机桌面 Agent 与远程 Agent |
| 内容范围 | 新增可配置内容类型和内容记录；首发不只包装现有图书接口 |
| 内容存储 | 内容类型定义存数据库，记录以结构化 JSON 存储；首发不做复杂关联和全文搜索 |
| MCP 接入 | 远程 Agent 使用 CMS HTTP MCP 端点；本机 Agent 由 CLI 启动 `stdio` 适配器，适配器调用同一 CMS HTTP 能力 API |
| CLI 职责 | 以接入向导为主：验证地址/Token、连接测试、生成通用配置、本机 MCP 启动；不首发实现完整内容管理终端命令 |
| CLI 分发 | 跨平台单文件可执行程序；不要求用户预装 Python |
| 客户端适配 | 首发生成通用 MCP 配置片段和说明，不自动改写 Claude、Cursor、VS Code 等厂商配置文件 |
| 角色模型 | 现有用户分组继续作为可复用角色；不另建第二套通用 Role 身份体系 |
| 内容授权 | 按“角色 × 内容类型 × 查看/新增/编辑/删除”授权；无字段级和记录级授权 |
| Token 归属 | 用户自己创建和拥有 Agent Token；管理员可查看元数据并吊销，但不能读取密钥 |
| Token 权限 | Token 只允许使用用户当前已有内容能力的显式子集；权限或组成员变化后立即收窄；Root 的后台管理旁路不会下放给 Agent Token |
| Token 生命周期 | 默认 90 天、最长 365 天、必须过期；用户改密或管理员重置密码时吊销该用户所有 Agent Token |
| 安全存储 | 密钥只展示一次，数据库仅存摘要；CLI 优先使用操作系统凭证存储或环境变量，不向普通配置文件写入密钥；无安全存储时不明文回退 |
| 部署约束 | 继续默认 SQLite、单机单进程、零外部中间件；不新增 Redis、消息队列、外部缓存或搜索服务 |

## 4. 首发功能范围

### 4.1 Web 管理界面

- 内容类型向导：名称、唯一标识、说明、字段及字段类型、必填规则和枚举选项；支持预览与示例数据。
- 内容类型字段首发支持：短文本、长文本、数字、布尔、日期、单选。
- 内容记录列表、创建、查看、编辑和软删除；保存时按当前模型校验。
- 分组权限页增加内容能力配置，按内容类型分组显示查看、新增、编辑、删除操作。
- 个人中心增加 Agent Token 管理：新建、一次性展示、元数据列表、吊销。
- 增加 Agent 接入向导：选择本机/远程方式、展示 MCP 地址、测试连接、生成通用配置和复制步骤。
- 新建入口应使用清楚的用户语言，不要求用户理解 JWT、数据库表名或代码权限名。

### 4.2 后端与 MCP 能力

- 新增可配置内容类型与内容记录 API；新 API 不改动现有 `/cms/**`、`/v1/**` 与 `/health` 路径语义。
- 增加只允许内容能力的用户 Agent Token；不得把普通登录 JWT 当长期 Agent 密钥使用。
- 新增 HTTP MCP 端点和本机 `stdio` 桥接，共用统一业务服务与授权判断。
- MCP 首发工具：发现当前可用内容类型、分页列表、详情、新增、编辑、软删除内容记录。
- MCP 不提供内容类型设计、用户、分组、权限、Token、系统配置等管理工具。
- 支持对已声明字段做基本标量相等过滤与创建/更新时间排序；不做全文搜索、复杂布尔查询或跨类型关联查询。
- MCP 工具说明及风险提示应准确标注只读和破坏性操作；软删除工具标记为破坏性操作。

### 4.3 CLI

- 单文件程序提供交互式 `init` / `test` / `config` / `mcp` 等接入流程，命令命名和最终参数以技术规格与实施阶段的官方文档核验为准。
- 保存 CMS 地址及非敏感选项；Token 使用操作系统凭证存储或调用环境变量，不保存到普通配置文件。
- 本机 MCP 配置只引用 CLI 命令、CMS 地址和环境变量占位符，不将真实密钥写入生成的配置片段。
- 提供不依赖厂商特定文件格式的标准配置片段；告诉用户如何粘贴到其 Agent 客户端。
- 连接测试只验证 HTTPS/本机地址连通性、Token 有效性和 MCP 能力发现，不执行写入操作。

## 5. 明确不做

- 多租户、组织架构与数据隔离。
- 独立于现有分组的通用 Role 管理体系、服务账号、OAuth/SSO、动态客户端注册。
- 字段级、记录级权限，审批流、发布工作流、回滚历史、版本分支。
- Agent 文件上传、富文本编辑、全文搜索、跨内容类型关系查询和任意 SQL/脚本执行。
- 向 Agent 开放用户、分组、权限、Token 和系统配置管理接口。
- 首发自动写入特定 Agent 厂商的客户端配置文件。
- Redis、消息队列、外部缓存、外部搜索服务、云托管账号系统。
- CLI 完整替代 Web UI 的内容维护与 CMS 管理命令。

## 6. 用户与安全规则

1. Agent Token 是单独的高熵不透明凭证，不是 access/refresh JWT；每个 Token 只属于一个用户。
2. Token 创建时必须选名称、到期时间、一个或多个内容类型，以及每个类型的允许操作；不得存在永不过期选项。
3. Token 可选范围不得超过创建者当前可使用的内容能力。Root 用户可显式选择内容能力，但 Root 管理员身份、用户管理权限及系统管理旁路永远不进入 Token 能力。
4. 每次 MCP/API 调用都依据当前数据库授权重新计算用户有效能力与 Token 范围的交集，不依赖前端隐藏控件，也不依赖长期缓存的授权结果。
5. 用户改密、Root 重置用户密码、删除用户时吊销其全部 Agent Token；用户组成员关系、内容授权或模型状态改变时，已有 Token 的能力即时收紧。
6. 管理员只能看 Token 名称、前缀、创建/过期/最近使用/吊销时间和所属用户，不能再次读取密钥。
7. Agent Token 明文不得进入应用访问日志、行为日志、异常堆栈、浏览器持久化或 CLI 普通配置文件。审计不得保存完整请求负载。
8. 远程生产连接必须使用 HTTPS；本机 `stdio` 仅作为本机进程，不开放额外监听端口。远程 HTTP MCP 应做来源校验、CORS 白名单与 DNS rebinding 防护。
9. 内容删除是软删除；记录与模型的每次操作都必须经过内容类型授权。Agent 不能通过改传模型标识、记录 ID 或字段名绕过服务端检查。

## 7. 验收标准

- [ ] 原有 32 个 API 的路径、字段、错误码和响应语义保持兼容；既有测试全部继续通过。
- [ ] 管理员可在界面创建内容类型；字段校验、字段变更和已有记录行为符合规格。
- [ ] 分组内容权限变化在下一次 API/MCP 请求生效，无需重启服务。
- [ ] 普通用户、无权限用户和 Root 用户的 Agent Token 均不能调用后台管理能力；Root Token 只能执行创建时显式授予的内容操作。
- [ ] Token 明文仅在创建响应展示一次；数据库、日志、CLI 配置和后续查询不含密钥。
- [ ] 到期、手工吊销、改密、管理员重置密码、用户删除及权限变化均有自动化测试。
- [ ] HTTP MCP 与 CLI `stdio` 暴露同一组内容工具并经过相同服务端授权。
- [ ] MCP 工具发现不暴露未经授权的模型；读、写、软删除及越权测试通过。
- [ ] CLI 在支持平台无需 Python 即可运行；配置生成不包含真实 Token；无安全凭证存储时明确要求环境变量或交互输入而不明文落盘。
- [ ] 用户可沿 Agent 接入向导完成地址检查、Token 验证、配置复制与只读连接测试；目标是不超过 5 分钟完成首连。
- [ ] 所有数据库迁移可在现有 SQLite 数据上向前执行；不改变旧数据表的既有含义，不要求旧用户重新登录。

## 8. 待技术规格固定的工程事项

以下是实现时必须核验、规格中按原则约束但不虚构版本的事项：MCP SDK 对 HTTP Streamable 与 `stdio` 的正式支持及稳定 API、HTTP MCP 鉴权扩展点、单文件打包工具与操作系统凭证库在目标平台上的可用性。实施前须阅读对应官方文档、锁定稳定版本，并进行最小兼容性验证；不因这些依赖引入独立部署服务。
