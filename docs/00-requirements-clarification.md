# Lin CMS 重构：需求澄清

> 文档版本：v0.1（待评审）  
> 日期：2026-10-19  
> 版本核验日期：2026-10-19  
> 输入材料：旧 Lin CMS Flask/Vue 实现（契约基线，参考仓库已于 2026-10-20 移除）、<https://ui.watermelon.sh/>  
> 关联文档：[规划计划书](./01-planning-proposal.md)、[实现实施方案](./02-implementation-plan.md)

## 1. 任务理解

在保留现有 Lin CMS 对外 API 契约与核心业务能力的前提下，重建两个独立可部署的工程：

1. **后端工程**：Python + FastAPI，替代现有 Flask 实现。
2. **前端工程**：React + TypeScript + Vite + Tailwind CSS + shadcn/ui + Watermelon UI，替代现有 Vue 3 + Element Plus 实现。

“功能基本复刻”指业务流程、页面能力、权限模型、接口语义和错误语义保持一致；“现代工程化”指类型安全、契约优先、自动化测试、CI、可选容器化、结构化日志和可观测性。视觉呈现可以重新设计，不要求与旧界面逐像素一致。

默认技术组合遵循“零外部中间件、依赖可控”：SQLite 为标准数据库，通过 ORM 支持 PostgreSQL/MySQL；允许并鼓励使用成熟的第三方库（ORM、校验、状态管理、测试工具等）；但不引入需要单独部署的 Redis、消息队列、外部缓存或搜索服务。

## 2. 现状事实

### 2.1 后端现状

| 维度 | 现状 |
| --- | --- |
| 框架 | Flask 3.1、Flask-SQLAlchemy、Flask-JWT-Extended、Spectree |
| 数据校验 | Pydantic v2 |
| 数据库 | SQLAlchemy 2.1，开发默认 SQLite，生产可切 MySQL/PostgreSQL |

| 路由数量 | 32 个（健康检查 1、用户 9、管理员 12、日志 3、文件 1、图书 6） |
| 行为日志 | 登录、注册、改密、删除用户、分组增删等操作写入 `lin_log` |
| 文件 | 本地存储，按 `YYYY/MM/DD` 分目录，MD5 去重，默认 2 MB/文件、20 MB/请求、10 个文件、仅 jpg/png/jpeg |
| 测试 | pytest，覆盖认证、用户、管理员、图书、日志、权限同步、会话撤销、加固项 |

| 维度 | 现状 |
| --- | --- |

| UI | Element Plus、SCSS、自定义主题 |

| 布局 | 可折叠侧边栏、侧边栏搜索、面包屑、多页签、返回顶部、全屏、用户菜单、移动端抽屉 |

### 2.3 现有契约的关键特征

- 路径固定为 `/health`、`/cms/**`、`/v1/**`，没有 `/api` 前缀。
- 成功/失败提示类响应使用信封：`{ message, code, request }`；查询类接口直接返回业务 JSON。
- 分页参数 `page` 从 0 开始，`count` 约束为 `0 < count < 16`。
- 登录返回裸对象 `{ access_token, refresh_token }`，没有 `token_type`。
- `GET /cms/user/refresh` 通过 `Authorization: Bearer <refresh_token>` 刷新。
- `GET /cms/user/permissions` 的 `permissions` 是 `[{ 模块名: [{ permission, module }] }]` 形式的数组，不是扁平数组。
- 权限由代码中的元信息在启动时同步到 `lin_permission` 表；仅 `mount=True` 的权限可分配给分组。
- `POST /cms/user/register` 实际是管理员创建用户，不是公开注册。
- 错误码与 HTTP 状态码并非一一对应；前端主要读取响应体 `code` 和 `message`。

### 3.2 建议保留（P1）

- 4 套主题色板的“能力”保留，具体色值可按新设计系统重做；至少提供浅色/深色与 2–4 套主色预设。
- 登录图形验证码（默认关闭，配置开启）。
- 接口限流：登录/刷新/登出/验证码 60 次/分钟，注册 30 次/小时。
- 日志搜索关键字高亮、日期快捷选项、无限加载。
- 头像裁剪。
- 无操作自动登出（默认 60 分钟，可配置）。
- 旧数据迁移脚本（可选、可重复执行）。
- 前端首页概览卡片（用户数、分组数、图书数、日志数），数据由现有列表接口汇总，不新增后端接口。

| 项目 | 原因 |

## 5. 角色与权限矩阵

| 角色 | 判定方式 | 可访问能力 |
| --- | --- | --- |
| 访客 | 无 token | 登录、验证码、公开图书列表/详情/搜索、`/health` |
| 登录用户 | 任意有效 access token | 自身信息、改密、登出、刷新；图书创建/更新 |
| 普通分组用户 | 属于非 Root 分组 | 在登录用户基础上，获得分组被授予的挂载权限（日志查询、日志搜索、日志用户清单、删除图书等） |
| 超级管理员 | 属于 `level=ROOT` 的分组 | 全部管理员接口与全部权限旁路；不可被删除；Root 组不可删除、不可添加用户 |

补充规则：

- 未加入任何分组的用户登录后仍可访问“仅登录”接口，但访问挂载权限接口会被拒绝。
- 管理员接口（`/cms/admin/**`）要求 Root 组；普通分组即使拥有同名权限也不可访问。
- 分组被删除后，其权限关联同步删除；分组下有用户时禁止删除。
- Guest 组与 Root 组不可删除；Root 组不在“所有分组”列表中展示。

## 6. 核心用户故事

1. **管理员登录**：输入用户名/密码（可选验证码）→ 获得双 token → 拉取个人信息与权限 → 进入工作台。
2. **会话续期**：access token 过期 → 自动用 refresh token 换新 → 重放原请求；refresh 失效 → 清理本地状态并回登录页。
3. **创建用户**：管理员填写用户名、邮箱、密码、分组 → 创建成功 → 新用户可登录，默认落入 Guest 组（未选分组时）。
4. **管理用户**：按分组筛选、分页浏览；编辑邮箱与分组；重置密码；删除非 Root 用户。
5. **管理分组**：查看分组列表；新建分组并勾选权限；修改名称/描述；删除空分组；内置分组不可删除。
6. **分配权限**：在分组权限页按模块全选/半选/单选权限 → 保存时只提交差异 → 目标分组用户立即获得/失去访问权。
7. **查看日志**：按关键字、用户、时间范围筛选；支持“加载更多”；关键字高亮；仅拥有对应权限的用户可见筛选控件。
8. **管理图书**：公开浏览/搜索；登录用户新建/编辑；拥有“删除图书”权限的用户删除；删除为软删除。
9. **维护个人资料**：修改昵称、邮箱；上传并裁剪头像；修改密码后所有旧 token 失效。
10. **响应式使用**：在移动端折叠侧栏、以抽屉方式打开菜单；页签与表格可正常操作。

## 7. 非功能需求

## 10. 风险与依赖

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 旧契约存在隐式行为（如 `is_admin` 按 ID 判断） | 迁移后行为变化 | 以测试锁定“应有语义”，并在变更记录中标注修正项 |
| Watermelon UI 是复制式组件而非稳定组件库 | 上游变更导致维护成本 | 组件复制进 `components/ui` 后由本项目维护；锁定来源版本与许可证 |
| 旧数据密码哈希为 scrypt | 需要兼容 Werkzeug 的 scrypt 格式 | 解析并校验旧 scrypt；登录成功后重哈希为 Argon2id |
| 日志表增长快 | 查询变慢 | 为 `create_time`、`username` 建索引；分页强制上限；预留归档策略 |
| 前端重写范围大 | 工期风险 | 先冻结契约与设计系统，再按页面并行开发；E2E 提前介入 |
| 通知/插件等死代码被误认为需求 | 范围膨胀 | 在本文档明确列为 Out of Scope |
